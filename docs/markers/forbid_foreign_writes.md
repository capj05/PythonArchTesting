# `forbid_foreign_writes`

Require encapsulation while the matched target function or method runs: an
attribute of an object may be assigned only by its own class's methods.

- **Category:** Runtime structure
- **Placement:** function- or method-body `__archtest__: Annotated[...]`
- **Runs only with:** `python-arch-test --dynamic`; without the flag the rule is
  `SKIPPED` and does not affect the exit code.

## Usage

```python
from pythonarchtesting.rules import forbid_foreign_writes
```

Python has no private attributes, so nothing stops a service from writing
`account.balance -= amount` instead of calling `account.withdraw(amount)`. The
two versions can compute the same balances; they differ in where the
account's rules live. Which code assigns an attribute is only reliably known
when it runs: the assignment can hide in a helper, behind an alias, or in
`setattr(obj, name, ...)`.

## Arguments

**Required:**

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `cases` | `list[dict]` | — | Call arguments that drive the code, see [Cases](../dynamic-checks.md#cases). |

**Optional:**

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `init` | `dict \| None` | `None` | Methods only: constructor arguments for every case. |
| `timeout_s` | `float` | `5.0` | Wall-clock limit per rule, in `(0, 60]`. |
| `severity` | `str` | `"error"` | Violation severity (`"error"`, `"warning"`, `"info"`). |
| `message` | `str` | `None` | Custom violation message override. |

## Example

```python
from typing import Annotated
from pythonarchtesting.rules import forbid_foreign_writes

from .account import Account


def transfer(source: Account, target: Account, amount: float) -> None:
    __archtest__: Annotated[
        None,
        forbid_foreign_writes(
            cases=[{"args": [
                {"$new": "account.Account", "args": ["ada", 100.0]},
                {"$new": "account.Account", "args": ["bob", 20.0]},
                30.0,
            ]}],
        ),
    ]
    source.withdraw(amount)
    target.deposit(amount)
```

A target that writes `source.balance -= amount` fails with
`case 0: bank:transfer sets Account.balance at bank.py:9`. Worked example:
[`example/rule_showcase/dyn003_encapsulation`](../../example/rule_showcase/dyn003_encapsulation/).

## What it checks

- Every attribute assignment (`obj.x = ...`, `obj.x += ...`, `setattr(obj,
  "x", ...)`) made while the case runs, on an instance of a class defined in
  the analysed project, by code under the project root.
- An assignment is allowed when the assigning code is a method of the object's
  class or of one of its bases — including `__init__`, properties' setters,
  class and static methods, and `__init__` generated by `@dataclass`. Another
  instance of the same class counts as the class's own business.
- Everything else is foreign: functions of other modules, module-level helpers
  of the same module, methods of other classes. Code nested in a method (a
  local function, a lambda) counts as outside it.
- The same rule covers changes that assign nothing, each reported with its
  `change` in `details.cases[i].writes`:
  - `mutated` — what a `list`, `dict`, `set`, or `bytearray` attribute holds
    changed: `account.history.append(x)`, `account.tags["k"] = v`,
    `random.shuffle(account.history)`. The message reads
    `bank:audit changes what is held in Account.history at bank.py:14`.
  - `deleted` — `del account.balance`, `delattr(account, "balance")`.
  - `bypassed` — an assignment past the class's `__setattr__`:
    `account.__dict__["balance"] = 0`, `object.__setattr__(account, ...)`.

  These are found by comparing the instances the case can reach — its
  arguments, the instance a method runs on, the project instances they hold
  (three levels deep), the project instances the project's modules hold in
  their global variables (`world.BAG`, or the rooms of a dict
  `world.ROOMS`), and every instance built while the case runs — before
  and after the code that can change them: a container method returning, a
  library function that was handed one of them returning, and project code
  whose bytecode changes state without a call. A change made by library code
  belongs to the nearest project code that called it; a method of the class
  that hands its own list to a library function still owns the change.

  A write to an instance the case reaches only through a module global
  names that global in the write's `held_by` (`world.BAG`), in the report
  (`... changes what is held in Bag.items (held in world.BAG) at
  actions.py:12`) and in its fact; an instance inside the global (a thing in
  the bag's list, a room of `world.ROOMS`) is named by it too. The label is
  taken when the case starts: an instance a global gets while the case runs
  has none, and one moved from one global to another keeps the first. Code
  that keeps its state in module globals (a game whose actions get only the
  words of a command) is so checked without handing the objects to the cases
  as arguments. A back-reference an owner's method writes into an item it
  receives (`thing.where = self` in `Room.add`) is a write to another class's
  object and is reported, by a task as an unclassified write; with the
  globals watched it shows up more often.

## What it does not check

- Changes inside objects an attribute holds other than the builtin containers,
  and inside containers nested in them (`account.rows[0].append(x)`): only the
  attribute's own value is compared. A container of more than 1000 items is
  compared by its length only.
- Changes made by threads the target starts may be attributed to the code the
  main thread was running.
- Instances of exceptions, enums, and classes outside the analysed project.
- Classes defined inside functions or created after a case started.
- What values are assigned. Results are never compared.

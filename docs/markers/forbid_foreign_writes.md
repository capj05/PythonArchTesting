# `forbid_foreign_writes`

Require encapsulation while the matched target function or method runs: an
attribute of an object may be assigned only by its own class's methods.

- **Category:** Runtime structure
- **Placement:** function- or method-body `__archtest__: Annotated[...]`
- **Runs only with:** `python-arch-test --dynamic`; without the flag the rule is
  `SKIPPED` and does not affect the exit code.

## Usage

```python
from pythonarchtesting.rules import forbid_foreign_writes
```

Python has no private attributes, so nothing stops a service from writing
`account.balance -= amount` instead of calling `account.withdraw(amount)`. The
two versions can compute the same balances; they differ in where the
account's rules live. Which code assigns an attribute is only reliably known
when it runs: the assignment can hide in a helper, behind an alias, or in
`setattr(obj, name, ...)`.

## Arguments

**Required:**

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `cases` | `list[dict]` | — | Call arguments that drive the code, see [Cases](../dynamic-checks.md#cases). |

**Optional:**

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `init` | `dict \| None` | `None` | Methods only: constructor arguments for every case. |
| `timeout_s` | `float` | `5.0` | Wall-clock limit per rule, in `(0, 60]`. |
| `severity` | `str` | `"error"` | Violation severity (`"error"`, `"warning"`, `"info"`). |
| `message` | `str` | `None` | Custom violation message override. |

## Example

```python
from typing import Annotated
from pythonarchtesting.rules import forbid_foreign_writes

from .account import Account


def transfer(source: Account, target: Account, amount: float) -> None:
    __archtest__: Annotated[
        None,
        forbid_foreign_writes(
            cases=[{"args": [
                {"$new": "account.Account", "args": ["ada", 100.0]},
                {"$new": "account.Account", "args": ["bob", 20.0]},
                30.0,
            ]}],
        ),
    ]
    source.withdraw(amount)
    target.deposit(amount)
```

A target that writes `source.balance -= amount` fails with
`case 0: bank:transfer sets Account.balance at bank.py:9`. Worked example:
[`example/rule_showcase/dyn003_encapsulation`](../../example/rule_showcase/dyn003_encapsulation/).

## What it checks

- Every attribute assignment (`obj.x = ...`, `obj.x += ...`, `setattr(obj,
  "x", ...)`) made while the case runs, on an instance of a class defined in
  the analysed project, by code under the project root.
- An assignment is allowed when the assigning code is a method of the object's
  class or of one of its bases — including `__init__`, properties' setters,
  class and static methods, and `__init__` generated by `@dataclass`. Another
  instance of the same class counts as the class's own business.
- Everything else is foreign: functions of other modules, module-level helpers
  of the same module, methods of other classes. Code nested in a method (a
  local function, a lambda) counts as outside it.

## What it does not check

- Changes inside a mutable attribute: `account.history.append(x)` does not
  assign an attribute of `account`.
- Deleting attributes (`del obj.x`), and assignments that bypass the class
  (`object.__setattr__(obj, ...)`, `obj.__dict__[...] = ...`).
- Instances of exceptions, enums, and classes outside the analysed project.
- Classes defined inside functions or created after a case started.
- What values are assigned. Results are never compared.
